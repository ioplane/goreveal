# GoREveal

GoREveal is a clean-room Go binary reverse-engineering platform.

Current repository state:
- architecture and planning docs are in place
- baseline references are inventoried
- Podman-first development environment is in place
- Sprint 1 is complete: ingest, format detection, `analyze`, first fixture, first snapshot flow
- Sprint 2 is complete: build info, `ELF` pclntab function recovery, package recovery, `inspect functions`, `inspect packages`
- Sprint 3 is complete: initial type recovery via `DWARF`, initial string recovery via `ELF` section scan, `inspect types`, `inspect strings`
- Sprint 4 is complete: initial `source-tree` projection from `DWARF` file paths and module-aware root filtering
- Sprint 5 is complete: deobfuscation/refinement scaffold plus first real passes and `deobfuscate` CLI
- Sprint 6 is complete: SQLite-backed persistence, `export sqlite`, and stored-run diffing
- Sprint 7 is in progress: differential validation against normalized `GoReSym`, `redress`, and `gore` outputs is green, including `redress` module-path parity, narrow `redress source` overlap, and the current user-function set (`main.main`, `main.helperAdd`, `main.helperBanner`)
- Sprint 8 is complete: stable `IDA`/`Ghidra` export contracts are implemented and both thin adapters are fixture-validated
- Sprint 11 is complete: source-tree package nodes aggregate multiple files by import path, carry package-level `function_count`, expose external source dependencies instead of silently dropping them, enrich recovered packages with `import_path`, `source_file_count`, and `module_local`, and annotate raw types with `package`, `import_path`, `source_file_count`, `module_local`, and `user_meaningful`
- Sprint 12 is active: continue landing tiny bounded runtime-semantic steps such as the current `types..etypes`, `pcHeader` / `funcnametab`, `cutab`, `filetab`, `pctab`, and `pclntable` bridges before any broad moduledata/typelinks refactor

- stripped ELF runtime validation is now part of the active Sprint 12 lane
- stripped ELF product contract is now explicit:
  - `inspect runtime` now shows whether `firstmoduledata_addr` came from bounded `.go.module` fallback through `firstmoduledata_from_go_module_fallback`
  - `inspect functions` now exposes bounded `package`, `import_path`, `module_local`, `source_file`, `source_line`, and `autogenerated` metadata instead of only raw symbol names and addresses
  - `inspect packages` keeps a useful `main` package surface through bounded `build_info.path` reuse, exposes external `import_path` directly from function recovery, and now explicitly marks whether a package is backed by real source evidence through `has_source_evidence`
  - `inspect types` degrades to `[]` instead of JSON `null` when no `DWARF` type surface exists
  - canonical `analyze` also exposes `types: []` when no truthful type surface exists, instead of silently omitting the field
  - if a truthful type surface exists without source-tree evidence, `main` types may reuse `build_info.path` as bounded module-local metadata and non-`main` types keep direct `import_path` truth from parsed type packages
  - `source-tree` returns a bounded fallback root plus module-local and external package nodes with empty file lists when no truthful file evidence exists, and now marks those nodes with `has_file_evidence: false`
- `inspect runtime` now exposes the bounded runtime contract directly, including the current stripped-fixture fallback-source bit for `firstmoduledata_addr`, instead of forcing operators to parse full `analyze` output
- `inspect strings` now exposes bounded absolute `addr` truth by combining existing region base addresses with candidate offsets, without broadening string-recovery scope
- `source-tree` now exposes explicit `has_file_evidence` on package nodes, so rich and stripped outputs clearly distinguish file-backed and fallback-backed nodes
- `inspect packages` now also exposes explicit `has_source_evidence`, so package navigation shows whether a package is backed by real source-file evidence or only by bounded fallback metadata
- `export ida` and `export ghidra` now also preserve string `address` from canonical string candidates, so thin RE-tool adapters do not need to recompute it
- `export ida` and `export ghidra` now also preserve bounded function navigation metadata (`package`, `import_path`, `source_file`, `source_line`, `module_local`, `autogenerated`) from canonical schema
- `export ida` and `export ghidra` now also preserve bounded type navigation metadata (`package`, `import_path`, `source_file_count`, `module_local`, `user_meaningful`) from canonical schema
- thin `IDA` and `Ghidra` adapters now prefer string `address` over `offset` when applying comments, while keeping `offset` as backward-compatible fallback
- deferred backlog now also includes a thin `JEB` integration/plugin layer over the same canonical export strategy used for `IDA` and `Ghidra`

Current highest-priority gaps:
- widening differential validation and documenting justified divergences
- extending the current bounded runtime-semantic layer without overclaiming cross-version support
- broader baseline evidence across more than one external tool and overlap surface

Current medium-term product direction:
- do not try to replace `IDA`, `Ghidra`, `JEB`, or `Binary Ninja` as a general RE suite
- instead, make `GoREveal` the strongest Go-native recovery, trust, and transfer layer that plugs into them
- strongest future differentiators currently identified:
  - Go code peeling / user-code isolation
  - Go version tracking / build correlation
  - Go metadata knowledge network

Current containerized verification entrypoints:
- `make lint` (staged `golangci-lint` policy imported from `gobfd`; currently green)
- `make test` (`go test ./...` with baselines mounted, plus plugin checks)
- `make test-differential`
- `make test-differential-report`
- `make test-plugins`
- `make test-snapshots`
- `make snapshot-update`

Operational note:
- run Podman verification sequentially; overlapping build/test runs against the same bind-mounted workspace can cause avoidable permission races in the Go toolchain cache
